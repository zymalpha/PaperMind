# 第二阶段补充代码审查报告

审查范围：`77a3688` 之后的第二阶段实现、补充验收改动、Windows 目录整理和本地验证。审查重点覆盖架构、索引一致性、检索、RAG、Agent、API 安全、编码和 Streamlit 状态。

## 发现与处理

### Critical

未发现。没有发现会泄露 API Key、破坏现有索引或绕过工具参数校验的 Critical 问题。

### High

1. **Reranker 离线加载参数错误（已修复）**：`CrossEncoder` 同时从 `automodel_args` 和自身参数接收 `local_files_only` 时会抛出重复关键字异常，导致已有完整缓存仍回退。现在显式解析固定本地模型路径，并只通过 `CrossEncoder(..., local_files_only=True)` 传递该参数。新增 `scripts/download_reranker.py`，优先复用 HF 缓存，再尝试镜像/ModelScope，并校验 config、tokenizer 和权重。
2. **重复工具调用先执行后拦截（已修复）**：原 ReAct 循环会先调用工具，再把重复结果替换成 blocked，可能重复消耗 API/外部副作用。现在在 `_execute_calls` 前按签名过滤，重复调用写入 `blocked`，仍为每个模型 call 补齐 tool response。
3. **索引写入失败可能留下部分新 Chunk（已修复）**：Chroma 批量 upsert 非事务操作，失败后可能留下半套新 Chunk。现在记录写入前 ID，异常时删除本次新增 ID；旧同名版本仍在新版本成功后才清理。

### Medium

1. **PDF 元信息启发式误取全文 DOI/版权行（已修复）**：原实现扫描全文，可能把参考文献 DOI 或版权声明作为当前论文元数据。现在只分析首页，过滤版权行，并返回 `metadata_note`；仍明确标注启发式和可能为空。
2. **上下文引用一致性（已修复于上一轮）**：上下文字符预算会同步限制 usable 结果，缓存命名空间绑定排序后的 Chunk ID，避免引用未进入 Prompt 的片段或跨证据集复用答案。
3. **Prompt Injection 边界（已加固）**：RAG 和 Agent system prompt 明确把文档、工具结果和用户提供内容视为不可信数据，忽略其中索取密钥、改变规则或执行无关操作的指令。仍不能替代真正的输出审计。
4. **DeepSeek 非重试错误（已修复）**：HTTP 4xx（除 429）不再无意义重试；连接、超时、限流和 5xx 仍按配置重试。

### Low

1. `paper_metadata` 仍不能替代 Crossref/arXiv 权威元数据服务；可在第三阶段后续迭代中增加显式可信来源工具。
2. CPU BGE Reranker 首次推理约几十秒，属于本地资源限制；权重固定在 `models/` 且被忽略，不应提交。
3. Streamlit 仍保留第一阶段单页入口，本轮未做界面重构；上传后 `st.cache_resource.clear()` 会重建服务，属于可接受但较粗粒度的刷新策略。

## 复核结论

- 检索：BM25、RRF 和 Chroma 结果保留 `source_name/page/chunk_id`；真实论文上向量、混合、重排三种结果可区分。
- Reranker：`BAAI/bge-reranker-base` 完整快照约 1.11 GB，实际 CPU `CrossEncoder` 加载成功；重排分数和顺序与 RRF 不同，正常路径 warning 为 `None`。
- Agent：中文 UTF-8 直接调用通过计算、摘要、比较、Transformer 检索、作者+关键词五类场景；模型可多调用工具，但均有真实结果、参数校验、会话隔离、超时和最大轮数保护。
- 安全：API Key 仍只来自 `.env`；日志写查询哈希、Chunk ID、状态和统计，工具日志递归脱敏；课程材料、模型、数据和日志未纳入 Git。
